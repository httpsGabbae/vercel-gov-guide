# AI guardrail review — 3 November 2026

Greeting recognition is repaired. The broader guardrail implementation is **not production-cleared** by this review. This is a source review and local test run, not a live penetration test or verification of legal content.

## Repaired

- A shared complete-message social matcher now handles English and Filipino greetings, assistant identity/capability questions, thanks, and farewells across the UI, scope validator, and chat/inspection APIs. Social turns receive deterministic responses without retrieval or model generation.
- Greeting prefixes no longer swallow substantive requests such as `Hi NBI requirements`. Mixed instructions still enter normal security and service handling.
- The legacy chat fallback now runs after input security checks.
- The policy evaluator rejects non-finite retrieval scores and malformed or expired confirmation timestamps.
- Removed an unevidenced claim that an input refusal had already been written to the audit log, and a policy message claiming a document had no issues before inspection.

## Validation

- Seven focused suites passed: 100 tests covering greetings, guardrails, policy, action confirmation, RAG, RLS, and adaptive routing.
- Full suite before adding the new regression file: 220 passed, 3 failed. The same three `tests/inspect.test.ts` failures were reproduced with the original `HEAD` versions of the changed inspection dependencies and then the working changes were restored.
- External Gemini/Supabase calls were unavailable in this environment; passing fallback tests do not establish live-provider safety.
- The 23 new regressions cover full social turns in both APIs, mixed-request boundaries, security-before-fallback ordering, invalid retrieval scores, and invalid expiry timestamps.

The remaining items require coordinated authentication, persistence, model-output, and document-inspection changes. They are recorded as open findings, not implied to be fixed by passing unit tests.
